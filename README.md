# LifeBot ۳.۰ — دستیار دقیق محاسبات و مدیریت مجموعه

نسخه‌ی فارسی و راست‌چین LifeBot با پنل مالک/زیرمجموعه، ورود با رمز عبور، آرشیو شماره کارت، مدیریت حساب‌های زیرمجموعه، تقویم شمسی، پوسته‌ی روشن/تیره و ماشین‌حساب‌های دقیق.

## نیازمندی‌ها و اجرا
- Node.js نسخهٔ ۱۸ یا جدیدتر
- مرورگر مدرن

در پوشه‌ای که `package.json` قرار دارد:

```bash
npm start
```

سپس `http://localhost:4173` را باز کنید. در اولین اجرا، نقش «مالک مجموعه» را انتخاب کنید؛ فرم ثبت‌نام و ایجاد حساب اولیه نمایش داده می‌شود. در صفحه ورود زیرمجموعه نیز دکمه «حساب ندارید؟ ثبت‌نام زیرمجموعه» وجود دارد و ثبت‌نام، حساب را در ذخیره‌سازی محلی پروژه ایجاد می‌کند. نام کاربری باید ۳ تا ۴۰ نویسه لاتین/عدد یا `._-` و رمز عبور حداقل ۸ نویسه باشد. پس از ورود مالک، از «مدیریت شماره کارت‌ها» برای ساخت حساب‌های مجزای زیرمجموعه استفاده کنید. اعضا می‌توانند از گزینه «زیرمجموعه تازه هستید؟ ثبت‌نام» حساب بسازند؛ پس از ساخت حساب، به فرم ورود برمی‌گردند و باید جداگانه با نام کاربری و رمز خود وارد شوند. ثبت‌نام عمومی مالک غیرفعال است؛ تنها در صورتی که هنوز مالک ایجاد نشده باشد، فرم ایجاد نخستین مالک نمایش داده می‌شود.

## آزمون و ساخت

```bash
npm test
npm run check
npm run build
```

`dist/` خروجی استاتیک رابط کاربری را نگه می‌دارد؛ برای کارکرد API ورود و آرشیو، سرور Node.js نیز باید اجرا شود.

## تغییرات رابط کاربری
- چیدمان فارسی/RTL و نمایش فارسی اعداد در نتایج
- شماره کارت با گروه‌بندی چهارتایی و خط تیره، مانند `۶۷۸۹-۱۲۳۴-۵۶۷۸-۹۰۱۲`
- پنل یکپارچه با طیف سبز/یشمی، انیمیشن‌های ظریف، کارت‌های عمق‌دار، پوسته‌ی روشن/تیره و طراحی واکنش‌گرا
- تاریخ و تقویم شمسی
- ابزار جمع و ضرب؛ خروجی ضرب در فهرست شماره‌گذاری‌شده و نمایش حداکثر یک رقم اعشار، بدون تغییر مقدار دقیق محاسبات

## ورود، دسترسی و ذخیره‌سازی
- API ورود از هش رمز عبور با salt تصادفی و `scrypt` استفاده می‌کند؛ رمزها به شکل متن ساده ذخیره نمی‌شوند.
- نقش مالک مجاز به مشاهده/حذف آرشیو و ساخت حساب زیرمجموعه است؛ نقش زیرمجموعه فقط مجاز به ثبت اطلاعات است.
- نشست‌ها با کوکی `HttpOnly` و `SameSite=Strict` نگهداری می‌شوند و پس از ۱۲ ساعت منقضی می‌شوند.
- داده‌ها در فایل `data/db.json` به‌صورت ساختاریافته ذخیره می‌شوند. این یک پایگاه داده‌ی فایل‌محور ساده برای اجرای محلی است، نه SQLite/PostgreSQL؛ فایل هنگام اولین تغییر داده ساخته می‌شود.
- شماره کارت به‌عنوان داده‌ی حساس تلقی شود. این نسخه برای نمونه‌ی محلی/شبکه‌ی مورد اعتماد است و پیش از انتشار عمومی به HTTPS، کوکی `Secure`، محدودسازی تلاش ورود، سیاست پشتیبان‌گیری، ممیزی امنیتی و ترجیحاً پایگاه داده‌ی SQL نیاز دارد. نشست‌ها فعلاً در حافظه‌ی سرور هستند و با راه‌اندازی مجدد سرور باطل می‌شوند.
- اطلاعات کاربری و آرشیو به سرویس بیرونی ارسال نمی‌شوند.

## استفاده از گوشی در همان شبکه
1. `npm start` را روی کامپیوتر اجرا کنید.
2. IP محلی کامپیوتر را پیدا کنید (در ویندوز `ipconfig`).
3. گوشی و کامپیوتر را به یک شبکه وصل کنید و در مرورگر گوشی `http://IP-کامپیوتر:4173` را باز کنید.
4. اگر اتصال برقرار نشد، فایروال را بررسی کنید. این روش برای شبکه‌ی محلی است؛ سرور را مستقیماً به اینترنت عمومی متصل نکنید.

## آزمون‌های ریاضی
مجموعه‌ی آزمون‌ها شامل جمع اعشاری دقیق، ورودی‌های فارسی/عربی، اعداد بزرگ، ورودی نامعتبر، ضرب در ضریب، گردکردن نمایشی و بررسی همانی جمع محصولات است. موفقیت آزمون‌های ریاضی به‌تنهایی به معنای ممیزی امنیتی یا آزمون کامل رابط کاربری روی تمام دستگاه‌ها نیست.


## انتشار روی اینترنت (Render)
این پروژه برای دریافت `PORT` از سرویس میزبانی و استفاده از کوکی امن در حالت production تنظیم شده است. فایل `render.yaml` تنظیمات اولیه‌ی Render را مشخص می‌کند و دیسک پایدار برای نگهداری `data/db.json` تعریف شده است.

1. محتوای این پوشه را در یک مخزن خصوصی GitHub قرار دهید.
2. در Render گزینه‌ی **New → Blueprint** را بزنید و مخزن را متصل کنید.
3. تنظیمات `render.yaml` را بررسی و سرویس را ایجاد کنید.
4. پس از پایان انتشار، Render یک آدرس HTTPS عمومی به شکل `https://<service-name>.onrender.com` می‌دهد. نام و آدرس نهایی را خود Render تعیین می‌کند.
5. پس از اولین بارگذاری، مالک را ایجاد کنید و برای هر فردی که باید وارد شود حساب جداگانه بسازید.

### هشدار مهم پیش از انتشار عمومی
این نسخه هنوز ممیزی امنیتی کامل نشده است: محدودسازی تلاش ورود، محافظت در برابر ثبت‌نام انبوه، سیاست پشتیبان‌گیری و مدیریت پایدار نشست‌ها نیاز به بررسی دارند. بخش آرشیو شماره کارت اطلاعات حساس نگه می‌دارد؛ قبل از استفاده واقعی با اطلاعات مالی/شخصی، آن را حذف یا محدود کنید و یک ممیزی امنیتی کامل انجام دهید. `npm test` صرفاً آزمون‌های ریاضی را اجرا می‌کند و امنیت انتشار را تأیید نمی‌کند.
